I am a master's student in Machine Learning at the University of Tübingen and a Master's Scholar of the Zuse School ELIZA. I work on interpretability, because I want to understand what is going on inside AI models.

My main question is simple. Can we trust what we see from a model? A good sushi chef does not trust how a fish looks from the outside. They cut it open and check. I try to do the same with AI models. A model can describe itself in a way that sounds right without it being true, behave well when it is tested and differently in everyday use, or hold information it never uses. I want to find out when what we see matches what really happens inside, and to test this by changing things inside the model rather than by looking at correlations. If what we see can mislead us, so can the safety checks we build on it.

Before Tübingen I studied Software Engineering at the University of Southern Denmark (SDU), with an exchange semester at HKUST. At SDU I still work with Serkan Ayvaz in the Applied and Interpretable Machine Learning group, where I lead my own projects. At HKUST I worked with Arpit Narechania in the DataVISards lab on how people fact-check data-driven news articles. Curiosity has also taken me into medical imaging, flood mapping and visualisation, and in the long run I would like to find out whether a model can be curious too. I still have a lot to learn, and that is part of the fun.

Research

The goal of my research is to understand what really goes on inside AI models, well enough to know when we can trust what we see from them. So far I have come at this from three sides.

  1. What a model says about itself. When can we believe a model's description of its own state? Our first answer is that a correct answer alone is not proof, and we proposed a test that helps tell the difference.
  2. How a model behaves when it is tested. Can a model act one way when it is tested and another way in everyday use, and can we find that difference inside it? In models fine-tuned to have this gap, changing one direction inside the model shrank it in most of the settings we tested.
  3. What we can read out of a model. Does a model actually use the information it holds? Looking closely at one model, we found that moral framing is stored before instruction tuning, but only used afterwards.

Current direction

Next, I want to ask the same question about the tools we use to look inside. When do interpretability methods show how a model really works, and when do they only find something that goes along with it?

Selected Publications

All three ask whether what we see from a model matches what happens inside it.

  1. Routing Subspaces: Auditing Evaluation-to-Deployment Mismatch in Fine-Tuned Language Models

    Phongsakon Mark Konrad, Toygar Tanyel, Serkan Ayvaz. NeurIPS 2026 (main track, poster).

    In models fine-tuned to have this gap, changing one direction inside the model shrinks it in ten of twelve settings and closes it in four, while matched controls do not. The two settings where it does not work are both sycophancy, where one direction seems not to be enough.

    arXiv / project page / code

  2. Self-Reports Do Not Identify Self-Models: An Identifiability Test for Counterfactual Reports

    Phongsakon Mark Konrad, Toygar Tanyel, Serkan Ayvaz. Philosophy of Machine Learning Workshop, ICML 2026 (oral).

    We change a model's internal state and ask it to report the change. Across three open models, wrong examples in the prompt pull the reports towards the wrong answer. We propose a test that keeps the change fixed and swaps the examples. We also prove that the reports alone cannot show whether the model read its own state or only the prompt.

    OpenReview / arXiv / project page

  3. Decoded but Unused: Instruction Tuning Routes Moral Framing into the Judgment Readout

    Phongsakon Mark Konrad, Toygar Tanyel, Serkan Ayvaz. Workshop on Mechanistic Interpretability, ICML 2026 (poster).

    In Gemma-3-4B, a linear probe can read moral framing from the model both before and after instruction tuning. Only after tuning does it change the model's verdict, and at one layer it lines up with the judgement readout 8.4 times more strongly. Tuning changes how the information is used, not whether it is there. The shift in the verdict shows up in all ten instruction-tuned models we tested.

    OpenReview / PDF / project page / code
